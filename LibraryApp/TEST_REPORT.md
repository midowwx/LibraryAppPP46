# Библиотека

## Объект тестирования
Консольное приложение LibraryApp.
Назначение: имитация работы библиотеки для управления каталогом книг. Приложение позволяет добавлять экземпляры книг, выдавать их пользователям (меняя статус доступности) и принимать обратно, а также осуществлять поиск по идентификатору.
Предметная область: классы Book (Id, Title, Author, IsAvailable) и Library (приватный список книг, методы AddBook, BorrowBook, ReturnBook, FindBook).
## Методика тестирования
1. Отладка (Debugging): пошаговое выполнение сценариев в Visual Studio  с использованием точек останова в методах BorrowBook, ReturnBook и FindBook. Отслеживание состояния коллекции и значений переменных в окнах «Локальные» (Locals) и «Контрольные значения» (Watch).
2. Ручное тестирование: выполнение сценариев через консольный интерфейс (ввод ID книг) для проверки бизнес-логики.
3. Статический анализ кода: использование встроенных анализаторов Visual Studio (IDE00XX, CAxxxx) и проверка уровня предупреждений (Warning Level) в свойствах проекта.

## Результаты инспекции кода
Был найден избыточный параметр.
1. В методе Main(string[] args) объявлен параметр args, который не используется в логике приложения.

Параметр string[] args удален из сигнатуры метода Main.

Было найдено нарушение инкапсуляции
1. Внутренний список книг в классе Library был доступен для модификации извне.

Поле списка помечено модификатором readonly, доступ к нему осуществляется только через методы класса.
## Итоги
Качество кода после исправлений значительно повысилось. Приложение стало отказоустойчивым: оно больше не падает при некорректном пользовательском вводе или ошибочных сценариях, а корректно обрабатывает их с информированием пользователя. Инкапсуляция данных библиотеки усилена благодаря модификатору readonly и строгой валидации при добавлении.
